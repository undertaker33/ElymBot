# T02-ToolSystem与节奏感reply+插件与平台接入+FAQ

基线为 `main` 提交 `16142395df5e586f050f0168bda2548dff8c0bc5`。产品范围按 2026-11-22 确认的决定执行。

## 目标

用户在 ElymBot 主会话和人格专属会话中使用同一个宿主 Agent，按顺序收到有节奏的分条回复。用户可在 App 内安装和管理官方 QQ、定时任务插件，连接 QQ 收发消息，并在主会话中管理定时任务。任务运行一次，回复写入主会话并发往所有已接入该主会话的平台。用户可通过常见问题和首次引导完成配置，并收到 App 正式版本的更新提示。

## 范围与规则

### 工具、消息与 Reply

- 复用顺序 ReAct 循环、ToolRegistry 和 HistoryRead。按发起身份、会话、渠道和已启用来源提供工具。逐个执行工具，实际调用前复查授权和安装实例，按调用 ID 回填受控结果，保留取消、超时和执行上限。模型的工具结果留在模型协议内，App 显示宿主负责的操作回执和错误状态。
- App、QQ 和定时任务使用同一个宿主 Agent。同一会话的执行与历史写入有序，不同会话可独立进行。基础消息支持文本、图片、语音、视频和文件段及稳定资源引用，记录账号、来源、发送者、消息 ID、时间、会话目标和引用关系。上下文、HistoryRead 与摘要服从同一会话及渠道可见范围，模型和投递按实际媒体能力处理。
- 主模型采用非流式完整响应。模型生成的用户可见内容一律由非终止 `reply` 工具提交。单次可提交多条文本和建议间隔，一轮也可在其他工具前后多次调用。宿主限制数量、长度和间隔，队列按消息顺序交付，入队后 Agent 可继续执行。兼容模型空白 STOP 可静默结束并保存该轮输入。仅返回普通正文且没有有效 Reply 时显示受控状态，正文不外发。现有模型的视觉路径继续可用。首发用实际配置的兼容文本模型验证，可优先复测 T01 已用的 `deepseek-flash`，以本期 Reply 实测结果为准。
- `reply` 成功回填表示已持久入队。分别记录生成状态和逐消息、逐目标的投递状态。待发、已送达、失败、回执未知和已取消均可区分。回执未知时先核对，禁止自动重发。生成中保留 T01 的忙碌规则，生成结束后可停止尚未交付的消息，发起下一轮也会取消该会话上一轮的尚未交付消息。回退取消被删尾部的待发并更新相关摘要。重开时恢复已完成轮次的有效待发，中断轮次取消原待发。能确认失败时可按单条、单目标重试。已有送达或未知副作用时禁用整轮重试。

### 基础 APK 与官方插件

- 基础 APK 可独立对话，随包安装启动 Ubuntu 容器所需的最小原生组件及宿主调度入口。原生范围按实际调用验证，以 proot、loader 和必要依赖为限。Ubuntu rootfs、Linux QQ、NapCat、插件实现及专用资产由相应插件按需下载。基础 App 保留现有最低 Android 版本，QQ 插件单独声明支持的系统版本和 ABI。
- QQ 和定时任务采用由 ElymBot 管理的独立签名插件文件包。首版只接入官方插件，安装前验证发布者、插件 ID、版本、兼容性和完整性，按 Android 动态代码只读要求从 App 私有目录加载。在「插件」页由用户下载安装、更新、启停和删除。首装后自动尝试启用，实际初始化成功后登记能力。启用失败保留已安装状态并可重试。更新保留启停选择，确认新版可用再切换；下载、校验或新版初始化失败时原可用版本继续运行。
- 停用、删除或安装实例更换使旧工具、连接、待触发任务和待发工作失效。停用和更新保留用户配置。删除 QQ 插件清理对应运行目录及登录态，用户可保留宿主侧设置和会话记录。用户明确选择同时清除时，删除对应插件数据并重置其引导。已由用户保留的任务数据在插件重装后仍可查看，旧安装实例的回调和待发工作不得恢复。
- 官方插件目录显示兼容性、安装状态与可用更新。GitHub 是权威目录及文件主源，Gitee 只在权威目录已验证且 GitHub 文件传输失败时，提供同版本、同摘要、同发布身份的文件。错误签名、摘要不符或不兼容制品均拒绝。Agent 可查询、解释和推荐官方目录条目；安装、更新、启停与删除由用户操作。
- App 每次新打开时检查一次 GitHub 正式版本，「关于」提供手动检查。匹配已安装包的可信数值版本，区分无更新、新版本和检查失败。发现更新时弹窗，由用户决定下载，并经 Android 安装器更新同包名、签名兼容的 APK。

### QQ 平台

- 首版为受支持 ARM64 真机上的单账号在线接入，沿用 Ubuntu/proot + Linux QQ + NapCat + OneBot，按 ON-04 路线在线准备。提供一键启动、可观察进度、失败重试、扫码刷新、状态、重连及退出。升级后重新核对安装库路径。验收锁屏或后台收发与断线重连，持续无人值守及开机自动在线另定。
- 本人手动绑定的 QQ 私聊与 App 共用主会话。其他私聊和群聊按接收账号及 D07 规则隔离，在 App 内只读。普通对话回复回到当轮触发目标。保留平常使用的群/私聊准入、管理员绕过、命令与别名、唤醒和屏蔽、限频丢弃与暂存重放、按成员隔离和获准的公共群历史。明确屏蔽或未经准入的消息不进入公共上下文，获准群的未唤醒消息可作为该群材料。平台事件去重后再创建执行。

### 主会话定时任务与多平台投递

- 定时任务仅归主会话。首版从 **App 主会话**打开任务列表、首次引导、编辑和「立即运行」，或在该会话用自然语言管理。人格专属会话、其他私聊和群聊均不提供任务入口或工具，QQ 在首版接收任务回复。直接页面路由及工具调用共用同一归属检查。
- 手动和自然语言入口管理同一任务记录，支持创建、查看、编辑、暂停、恢复、删除和从任务详情立即运行。模型提出的创建、修改、暂停、恢复与删除，经用户确认后才生效。记录标题、提示词、时区、时间、一次或重复规则、结束条件、启停和运行历史。
- 到期或用户从主会话立即运行时，使用主会话和生效人格调用同一个宿主 Agent。主会话忙碌时排队。每个任务的同一计划时点只产生一次执行，手动运行单独记录，保持原计划。采用系统可延迟调度。恢复时每项任务最多补执行最近且距计划时间不超过 **15 分钟**的一次到期，超窗记为错过。15 分钟是任务补执行窗口。
- 每次任务执行只生成一轮回复。每条回复在 App 主会话记一次，并发送到当轮首条 Reply 入队时所有已启用、已接入且有主会话接收授权的平台。本期 QQ 的外部目标是已绑定到主会话的本人私聊；其他私聊、QQ群和历史联系人不属于该投递目标。没有外部平台时回复仍可在 App 主会话查看。
- 各平台分别按顺序投递和记录状态。发送前复查插件启停及绑定，失效目标不接收旧回复。平台断线或部分失败时，App 主会话及其他平台照常接收。单目标重试只影响该目标，已确认送达的目标不重发，回执未知沿用 Reply 通用规则。普通聊天仍按触发渠道回复。

### 常见问题与首次使用

- 「设置 → 常见问题」常驻，支持设置搜索、分类、搜索问答、展开单条回答及跳转。由 App 随版本维护条目，随插件安装与启用状态跳转到功能页或插件详情，可从 FAQ 手动重开首次配置。
- App 首次配置复用添加模型服务、选择对话模型和能力验证入口。存在有效文本模型分配且具有首版 Reply 所需能力时可完成配置，首聊成功单独核验。无可用主会话时复用人格创建或激活。跳过后由用户从 FAQ 重新发起，恢复时按实际配置重算。升级时已有有效配置直接使用，能力不足可从配置修复。
- QQ 首次进入平台页后可一键启动，有有效登录态则重连，否则扫码。OneBot 连接可用才完成。定时任务首次引导从 App 主会话入口开始，首次手动创建或经确认的工具创建成功后完成。失败可重试，停用及更新保留状态，主动清理相关数据后重置。

### 依据与边界

- [T02 页面原型](ElymBot_T02.html) 是本期页面与交互依据。任务入口及权限、回复投递和制品范围以本任务书为准。原型中模拟的版本、模型、制品体积、账号和运行结果是示例，正式界面文案遵循 [界面约束](../../rules/界面约束.md)。
- 页面按原型复现，并为导航切换、搜索展开与收起、弹层、FAQ 问答展开及可见状态变化保留对应过渡。启用系统减少动态效果时，操作和状态反馈仍完整可用。
- 本期延续 [产品决策与 QQ 规则](../../product/ElymBot-重构前功能盘点.md)、[Minimal Core 运行边界](../../architecture/ElymBot-Minimal-Core设计.md) 和 [T01 交付证据](../T01-Core和基础app重构/feedback/W01-总控与集成-feedback.md)。T02 采用本任务书确认的插件制品、定时任务归属和回复目标。独立 DEX、随 APK 安装的 proot 执行最小 Ubuntu 命令以及 Android 调度入口已有真机探针证据，正式插件接入由本期验收。
- 本期范围含官方插件目录及已列出的平台。第三方插件及 SDK、远程 MCP、音频识别与合成、音色克隆、App 媒体录制、视频理解、地理围栏、多个 QQ 账号同时在线、离线 QQ 资源版，以及旧 ElymBot 的插件 API、备份和运行时迁移留待以后。
