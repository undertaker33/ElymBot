## 背景与目标

T01 已交付独立基础 App、单宿主 ReAct、原生流式回复、HistoryRead 和会话检查点。T02 从 `main` 提交 `16142395df5e586f050f0168bda2548dff8c0bc5` 扩展工具、消息和平台能力。用户可接收分条延时回复，从 App 内独立装卸 QQ 和定时任务插件，并借助 FAQ、首次引导和更新检查完成使用。

当前 App 从 [ElymBotApplication](../../../app/src/main/kotlin/com/elymbot/android/ElymBotApplication.kt) 装配宿主，平台和插件页显示空状态。现有 Core 原生流式和工具失败反馈可直接进入聊天，且历史投影按完整轮次处理；T02 切换出口与持久状态时需要保留既有历史、模型配置和检查点。

最小探索证据包括实际 Core 网关的非流式合成工具调用、SQLite 投递状态、合成双源校验，以及 ARM64 真机分离 DEX、随 APK 安装的 proot 执行 Ubuntu 命令和系统调度回调。正式组合采用宿主随包的最小启动组件和两个独立签名文件包。正式安装生命周期、账号、模型、后台恢复和双源发布仍以本期端到端证据验收。

## 交付边界

| 能力 | 边界 |
| --- | --- |
| Tool System | 同一 Agent 按身份、来源、会话与有效安装授权提供工具。按顺序执行并按调用 ID 回填；执行前复核权限与安装实例；保留取消、超时及上限。用户可见回执由宿主提供。 |
| 统一消息与 Reply | 基础消息携带类型化媒体、稳定引用和平台身份。主模型用非流式完整响应，Reply 是模型正文的出口。支持同次多段、多次工具调用和成功静默，保留视觉与 HistoryRead。 |
| 会话与投递 | App 拥有会话、有效历史和路由授权，Core 保持 Kotlin/JVM 独立。持久入队先于工具成功；生成与逐消息、逐目标的投递分开。失败和未知有可观测状态。 |
| 宿主与插件 | 基础 APK 内含实际必需的 proot、loader 及原生启动依赖与调度入口。QQ、定时任务实现、Ubuntu rootfs、Linux QQ、NapCat 和插件专用资产按需取得。App 私有目录加载经签名验证的官方文件包，启停及重装以有效安装身份为边界。 |
| QQ | 首版为 ARM64 单账号，采用 ON-04 在线准备路径。绑定本人私聊接续主会话，其他私聊、群聊隔离且在 App 只读。按 D07 保留管理及命令、准入、唤醒、限频、隔离和获准的公共历史。 |
| 定时任务 | 仅从 App 主会话创建、查询、管理和立即运行。任务数据由插件持有，模型写操作经用户确认。一次到期只执行一轮，同一回复送到主会话及所有有效接入平台。 |
| 分发与更新 | GitHub 权威目录和主文件源，Gitee 仅作为已知同一签名制品的文件备用。Agent 查询或推荐；用户执行安装操作。正式 App 更新按数值版本和签名兼容，经系统安装器。 |
| 页面与引导 | 按用户提供的原型实现聊天、官方插件、QQ 平台、主会话任务、FAQ、首次配置和关于页更新。保留页面切换、搜索、弹层、展开收起及状态变化的过渡，遵循系统减少动态效果及现有界面约束。正式文案全部资源化。 |

## 关键行为

- 工具公开目录、执行检查和结果回填用同一注册链。凭据留在各认证实现。App 的独立 Room 数据、权限和组件由 App 拥有；插件经当期真实用到的窄契约接入。官方插件同宿主进程运行，共享 Android 权限，信任边界为发布身份与宿主授权。
- 空白 STOP 可成功静默并保留输入。只有普通正文时给受控状态，正文不外发。已成功投递的消息、成功静默轮次、失败和部分生成分别投影，旧数据照常读取。真实模型优先复测 T01 使用的 `deepseek-flash`，以本期可选工具调用的实际结果为依据。
- 同会话按序执行和投递。用户停止、开始下一轮和回退按任务书取消仍可取消的旧待发；允许重开后恢复仍有效的已完成轮次待发。外部效果未知时核对真实状态，已确认送达不重发。整轮重试须无已知或可能的外部副作用，已确认失败的单条可针对单目标重试。
- 普通会话回复回原触发目标。定时任务一次到期或手动运行仅创建一个主会话轮次，主会话忙碌时排队。第一次 Reply 入队固定当轮有效目标，发送前复查授权和安装身份。App 记录一次，每个有效平台各自投递；QQ 只发给绑定的本人私聊。部分目标失败不影响其他目标。恢复只补最近且迟到不超过 15 分钟的一次到期，该窗口为业务规则。
- 插件安装、升级的校验与初始化完成后才切换，失败保留可用旧版。停用、卸载或实例更换使旧工具、连接、计划回调与待发失效。按用户选择保留业务数据。删除 QQ 运行目录和登录态，重装按实际状态引导。退出首次配置后通过 FAQ 续接；已有符合条件的配置在升级时可直接使用。

## 验收

- 核对基础 APK 的构建依赖与实际制品，证明原生启动组件存在、可选插件及专用资产独立。使用真实签名插件走 App 内下载、验证、安装、启停、更新与清理入口。
- 使用合成模型及适配器覆盖可判定的调用、并发、状态失败和多平台扇出，再在真实模型和受支持 ARM64 设备验证 Reply、QQ 和系统调度。
- 从现有 T01 数据升级与干净安装两条路径验证会话、模型、视觉、历史和检查点；用真实页面验收发现、首次使用、FAQ 和更新操作。
- 每个验收项使用 [任务书 A01–A17](T02-ToolSystem与节奏感reply+插件与平台接入+FAQ.md#用户验收) 与 [Checklist](T02-ToolSystem与节奏感reply+插件与平台接入+FAQ-checklist.md) 判定。录明测试环境、命令或操作、制品与证据等级。
