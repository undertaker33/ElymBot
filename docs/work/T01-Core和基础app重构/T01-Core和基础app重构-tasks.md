## 交接契约

| 提供方 → 消费方 | 交接内容 |
| --- | --- |
| W02 → W03/W04 | 模型引用绑定服务与模型 ID。模型请求返回可取消的文本增量和终止结果，或结构化工具调用批次。正文、调用 ID、参数、结束原因及超限错误可区分。探测三态含未确认。凭据仅经认证边界送给适配器。 |
| W04 → W03 | 每次运行绑定当前会话 ID 和该会话内稳定轮次上界，分页返回保留原文；摘要提交核对覆盖边界，写入候选时不改原文。可见聊天不依赖模型上下文选择。 |
| W03 → W04/W05 | 指令解析给出行为和参数；Agent 发出带执行标识的文本增量、助手工具反馈和终止状态。工具来源提供稳定 ID、描述、作用范围与可取消执行入口；结果按调用 ID 回填。 |
| W04 → W05 | 发送、停止、重试、切人格、保存指令名与模型配置入口，按会话提供持久化历史和执行态。UI 不直接改 Room 或运行 Agent。 |
| W01 → 各组 | 所需项目依赖、接口定义与字段语义。先完成共享接口交接，再分别实现；后续接口缺口由 W01 在共享文件统一处理。 |

- 历史读取参数是稳定轮次序号的闭区间，序号允许空洞。缺省取最近一页，页内按时间正序，续页边界按查询方向给出。单条记录超预算时返回截断标记，续页仍可推进。读取上界排除本次用户输入，回退后的有效记录从存储重读。带停止或中断状态的可见残片若返回，须附状态。指令回执和工具展示文本只用于界面。
- 轮次标识与尝试标识分离。重试只处理仍在会话尾部的失败轮，复用原用户消息；当前输入只装配一次。过期回调按尝试标识丢弃。超限恢复只重发当前模型请求，继续沿用已完成的工具结果。
- 检查点删除按建点顺序判定后续点，覆盖多个检查点锚在同一轮的情况。回退到空点的回执属于即时操作反馈，重启后回退的会话仍为空。

## T01.01 模块基线与交接契约

- 负责人 W01。前置 无。
- 目标 确定所需 Kotlin/JVM 与 Android 依赖、网络权限和测试接入；核对 Core 独立于 Android。冻结下文交接语义，W02–W05 使用同一契约。
- 写入范围 `core/build.gradle.kts、app/build.gradle.kts、gradle/libs.versions.toml、app/src/main/AndroidManifest.xml`、`core 下 contract 包内的模块间接口`。
- 参考 详细设计 §1–3、§6、§8。
- 完成边界 通过 Core/Android 编译，交接接口已可被消费；验收以模块编译与依赖检查为入口。

## T01.02 模型适配、能力探测与 SSE

- 负责人 W02。前置 T01.01。
- 目标 实现模型列表、三项探测、普通响应、真增量、终止和错误语义。结构化工具能力需能从实际配置或探测链路判定，仍沿用原型三项可见结果。视觉直答和转述由 Agent 使用适配契约编排。
- 写入范围 `core/src/main/kotlin 下 model 包及对应 JVM 测试`。
- 参考 详细设计 §6.2–6.3 的原型、旧 ElymBot 和 Re-UthCode 定位。
- 完成边界 本地合成 HTTP 服务验证首增量先于结束、UTF-8/空白保留、工具参数分片、普通响应、提前 EOF 和取消。

## T01.03 上下文装配、预算与压缩

- 负责人 W03。前置 T01.01。
- 目标 装配人格、历史、当前消息与完整工具批次，按实际模型预算计量。优先压缩旧完整轮次，必要时压缩本轮较旧工具批次。校验降幅、覆盖范围与有效历史，受限裁剪及超限恢复。
- 写入范围 `core/src/main/kotlin 下 context 包及对应 JVM 测试`。
- 参考 详细设计 §5.1–5.2 的 ContextCompiler、完整轮次选择和候选降幅校验。
- 完成边界 合成预算和摘要服务证明重复压力、覆盖范围、失败保留有效摘要、裁剪与硬超限行为。原文仍由历史仓库保存。

## T01.04 顺序 ReAct、工具底座与指令规则

- 负责人 W03。前置 T01.03；T01.01 的模型契约。
- 目标 实现顺序 ReAct、结果回填和续轮，衔接视觉路由与原生增量。实现来源登记、作用范围、取消、工具限量和 HistoryRead 分页。解析可改名的五种指令并返回类型化本地动作。
- 写入范围 `core/src/main/kotlin 下 agent、tool、command 包及对应 JVM 测试`。
- 参考 详细设计 §4、§5.3、§6.1–6.2、§8。
- 完成边界 用合成适配器验证完整批次、拒绝、失败、超时、取消、续轮及助手文本事件；用测试工具来源和 HistoryRead 验证共用入口。

## T01.05 Android 本地数据与检查点

- 负责人 W04。前置 T01.01。
- 目标 实现固定主会话、按人格固定归属的专属会话、人格、服务和用途、探测结果、指令名、历史与摘要的 Room 存储，按服务保存凭据；私有附件、封面与头像位置、会话未读状态。实现回退事务、建点、稳定序号、分页、批量删会话及人格删除的引用校验。
- 写入范围 `app/src/main/kotlin 下 data 包及 Android 存储测试`。
- 参考 详细设计 §3–5 中的 Room、旧消息实体及仓储、Re-UthCode 稳定位置。
- 完成边界 验证主会话唯一、专属会话归属及按人格列出。逐会话验证重启、实际删尾、摘要失效、空点、显示编号复用、事务回滚及历史隔离。

## T01.06 App 会话服务与持久化接线

- 负责人 W04。前置 T01.02、T01.04、T01.05。
- 目标 按会话串行接入指令、主会话人格切换、专属会话创建及读取、Agent、执行状态和持久化。每轮读取最新人格并捕获快照。按会话持有独立运行，接通导航后增量、最终落盘、新消息状态、取消、迟到事件过滤、中断、恢复与重试。接通历史与摘要存储契约。
- 写入范围 `app/src/main/kotlin 下 session 包和该层测试`。
- 参考 详细设计 §2–6；任务书用户验收。
- 完成边界 通过同一会话服务从发送到结束，验证重试不会重复用户消息，旧执行不能写回已删记录，HistoryRead 命中所属会话的真实仓储，其他会话的记录不可读。
