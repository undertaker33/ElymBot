# T01-Core和基础app重构

## 目标

用户安装基础 APK 后，可管理人格和模型服务，在全局主会话和人格专属会话中进行文字和图片对话，查看模型原生流式回复，通过 Slash Command 管理主会话人格和当前会话的检查点。宿主 Agent 能调用 `HistoryRead` 取回当前会话历史，接续完成当前请求。

## 范围与规则

[T01 详细设计](T01-Core和基础app重构-详细设计.md)列出首版能力、模块职责、存储与执行设计、插件底座交付口径、参考源码和验证方法。

### 界面与模块

- 以 [ElymBot 高保真原型 v0.6.3](ElymBot_高保真原型.html)作为界面基准。点击人格封面进入主会话，从主会话右上角的「会话」进入对应人格的专属会话列表。专属会话发送首条消息后入列，初始标题取首条消息，按最近活动排序，支持改名，返回时回到所属人格的会话列表。指令、检查点和工具反馈使用现有聊天布局，指令改名提供对应的设置入口。界面文案遵循 [项目规则](../../../AGENTS.md#界面与-pr-文案)。
- `core/` 承载单一 Agent、ReAct 循环、上下文装配与压缩、模型接入、工具执行和通用指令规则。`app/` 承载 Android 界面、依赖装配、人格与会话数据、检查点的持久化操作、模型配置及凭据存取。
- App 固定保留一个全局主会话，使用当前激活的人格，切换后接续同一历史。用户可从对应人格入口创建和打开专属会话，创建时固定归属人格。各会话分别保存历史、摘要和检查点。每轮读取所属人格的最新配置，已经开始的回复沿用本轮启动时的配置。人格数据包括名称、标签、封面和提示词。封面和聊天头像可分别调整图片位置，保存后在各自位置生效，重启后保留。基础 APK 独立运行。独立 Bot 档案、平台与插件能力、深浅色切换、语言切换、更新、备份恢复、日志和缓存管理留在 T01 之外。界面字符串按项目规则资源化。

- 专属会话支持单条及批量删除，批量选择范围为当前人格的会话列表。删除人格前须处理完其名下专属会话。正在生成的会话可以先停止或等回复结束后删除。
- 不同会话可以同时生成。返回列表、离开聊天或切换会话时，原会话继续接收增量并保存最终回复。重新进入时显示已生成的内容。离开期间收到新回复时，在应用内提示对应会话有新消息，查看后清除该提示。

### 模型服务与对话

- 首版仅接入 OpenAI 兼容协议。用户可新增、编辑、删除服务，配置服务地址、API Key 和模型 ID，拉取模型列表或手动填写模型 ID，选择主模型和视觉模型。服务配置和凭据在 App 重启后仍可使用，凭据由 App 按服务存取，仅用于认证。
- 能力探测显示模型可用性、视觉输入和原生流式三项结果。探测请求实际调用所选模型。连接失败、认证失败或其他无法判定的情况应显示对应状态。原生流式探测依据服务实际返回的文本增量。
- 模型支持原生流式时，App 收到文本增量即更新聊天气泡。模型仅支持非流式时，在完整回复返回后一次显示。已经开始的流式回复如遇断流，标记中断并提供重试。用户停止或连接中断时保留已显示文字并标明状态。重试沿用原用户消息。可用的模型和凭据未配置时，提示用户前往模型配置。
- 带图消息优先由支持视觉的主模型直接回答。主模型不支持视觉时，由配置的视觉模型将图片转述为文本，再由主模型结合用户问题和转述回答。缺少可用视觉模型时给出配置提示。最终回复沿用主模型的流式能力。

### Slash Command 与检查点

首版支持以下五个固定行为。用户可以自定义 `/` 后的名称，参数用空格分隔。指令在本地执行，列表与回执使用纯文本。`/help` 显示当前指令名称、参数和用途，并写清两条回退指令的实际删除范围。

| 默认指令 | 行为 |
| --- | --- |
| `/help` | 列出可用指令及用法。 |
| `/persona`、`/persona N` | 在主会话列出按顺序编号的人格并标记当前人格，或按编号切换并继续该会话。专属会话的帮助仅列该会话可用的指令。 |
| `/checkpoint`、`/checkpoint N` | 按顺序列出检查点并标记当前检查点，或回到指定检查点，彻底删除该点后的对话和后续检查点。每个会话的第 1 个检查点固定为空，回到它会清空当前会话的聊天内容。 |
| `/reset` | 回到当前检查点，保留该点及以前的对话，彻底删除其后的对话和检查点。 |
| `/mark` | 在当前已完整结束的对话轮次创建检查点，并设为当前检查点。编号接在当前保留的检查点之后。 |

- `/reset` 和 `/checkpoint N` 在指令有效时直接执行。编号无效时返回用法或列表。当前会话生成结束后才可创建检查点或回退。主会话在生成结束后可切换人格。停止或中断的半截回复不可作为建点边界。
- 回退后，被删消息和后续检查点从持久化历史中删除。覆盖已删内容的摘要和关联的工具记录一并清理，`HistoryRead` 和后续模型请求均无法读回已删内容。回退后新建的检查点可重新使用已经释放的显示编号。

### 上下文与 HistoryRead

- Core 依据当前人格、所用模型的上下文预算、当前会话仍保留的历史、当前输入和工具结果装配请求。接近预算时对较早的完整轮次或已完成的工具批次做摘要压缩，每次调用前重新检查预算，压缩后的请求使用有效摘要及需要保留的原文。压缩保留原始聊天历史，用户仍可浏览。
- `HistoryRead` 随基础 APK 可用，是宿主 Agent 的内置工具。模型可调用它按范围读取当前会话中仍保留的历史，包括已被摘要替代的原文。单次读取按预算返回，保留消息顺序和可定位的范围。检查点回退已删除的内容无法读取。
- 支持结构化工具调用的模型可发起工具请求。宿主收齐并校验调用后顺序执行，按调用 ID 回填结果，再由模型继续处理。面向用户的工具反馈用当前助手身份发普通文本消息，使用现有气泡。执行保留停止、超时和轮次上限。

### 依据

- 指定原型 v0.6.0 已用 Chromium 和本地合成 HTTP/SSE 响应验证人格搜索与共用聊天、模型列表和探测入口、首段先于结束帧显示、提前断流和停止。T01 的图片路由、非流式交付、指令和工具按本任务书的规则验收。
- [Minimal Core 设计](../../architecture/ElymBot-Minimal-Core设计.md#运行边界)提供 App、Core 和插件边界及上下文预算依据。检查点删除、图片路由、原生流式和 T01 范围采用 2026-11-13 确认的任务书规则。
- 旧 ElymBot `4b19ba4` 的图片转述和 Compose 聊天作为参考。其 App 交付链会等待模型请求完成后分段发送。Re-UthCode `0a478e8` 的 20 项定向测试通过，覆盖合成增量、取消、断流、工具执行与结果回填、摘要和指令解析。SQLite 合成探针验证了事务回滚、删除后续数据和复用检查点编号。这些结果作为探索依据，Android APK 和实际模型服务在实施后验收。 [流式事件参考](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events) · [Android 数据和界面架构](https://developer.android.com/topic/architecture/recommendations)

## 用户验收

| 前置条件与操作 | 可观察的预期结果 |
| --- | --- |
| 安装基础 APK，打开人格库，搜索或按标签筛选，创建一个含封面和提示词的人格，进入主会话，再分别从两个人格的入口创建并打开专属会话。 | 界面与对应原型一致。主会话固定存在，各专属会话只在归属人格的入口可见和可打开。重启后保留人格归属、主会话激活状态和各自历史。 |
| 新增一个 OpenAI 兼容服务，拉取模型列表，选择主模型并运行能力探测。再重启 App 并发送消息。 | 可管理服务和模型用途。探测分别显示模型可用性、视觉和原生流式结果。重启后仍可用已保存的服务发起请求。 |
| 用可分段发送的测试服务发送文字。服务端在发首段后暂缓第二段和结束帧，再继续发送。另切换至仅支持非流式的模型。 | 流式首段在服务端继续发送前已显示，后续增量追加到气泡。非流式回复在完整返回后一次显示。 |
| 在已显示部分回复时分别停止生成和模拟连接中断，再重试中断的请求。 | 可见的半截回复保留并标明状态，停止后无后续增量。重试复用原用户消息，聊天中没有重复用户消息。 |
| 分别用支持视觉的主模型、需要视觉模型转述的主模型发送图片。再移除可用视觉模型测试第二种情况。 | 测试服务可观察到直接带图请求，或先带图转述、再以文本交给主模型的两步请求。缺少可用视觉模型时 App 给出配置提示。 |
| 在主会话运行 `/help`、`/persona`、`/persona 1`，把人格指令改名后重试，再到专属会话核对帮助并尝试切换。 | 主会话帮助显示实际用法和删除范围，编号切换人格后继续同一历史。改名生效。专属会话保持创建时的人格，帮助只列可用指令。 |
| 在一个专属会话聊完 A、B 后用 `/mark` 建点 2，再聊 C、D 并建点 3。回退到点 2，继续聊 E、F 再建点。再发送一轮并执行 `/reset`，最后执行 `/checkpoint 1`。 | 回到 2 后立即删除 C、D 和旧点 3。新点 3 对应 A、B、E、F。`/reset` 只删除新点 3 之后的内容。回到点 1 后该专属会话聊天内容清空，其他会话保留原历史。重启后结果一致。 |
| 用可控输入触发摘要压缩，要求模型引用一条较早消息。再从另一会话尝试读取该消息。最后在原会话回退到这条消息之前，用相同条件请求读取。 | 压缩后 `HistoryRead` 可读回原文，聊天中可见助手文本反馈，模型收到结果后继续回复。另一会话只返回自己的历史。回退后，聊天历史、`HistoryRead` 结果和后续模型请求中均无已删内容。合成失败结果也能回填并继续本轮。 |
| 编辑一个已有关联会话的人格的提示词，重新进入该人格的专属会话发送消息。再调整封面和头像的位置并重启 App。 | 下一轮请求使用更新后的提示词，原会话归属和历史保留。封面和头像分别应用保存的位置。 |
| 在同一人格下建立多个专属会话，尝试删除人格，再在会话列表批量删除。 | 人格删除提示先处理名下会话。一次操作删除所选会话及其历史、检查点和摘要，未选会话及其他人格的会话仍可打开。清空名下会话后可以删除该人格。 |
| 在 A 看到流式回复首段后离开，进入 B 发起回复。A 继续输出时切回查看一次，再离开 A，等 A 结束后从入口重新打开。 | A、B 的请求存在重叠，输出分别归入原会话。第一次返回 A 时显示此前已收到的全部增量并继续更新。A 在页面外完成后保存完整回复并提示新消息，查看后清除提示。 |

**交付物** 供安装验收的基础 APK，以及覆盖真流式、视觉两条路径、指令、检查点、`HistoryRead` 和会话并行与管理的可复现验证记录。
