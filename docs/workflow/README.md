# ElymBot 工作方式

## 选择任务方式

- **正式任务。** 有多个需要事先确认的用户行为、验收场景或产品取舍时，复制[任务书模板](templates/任务书模板.md)。填写用户要能做什么、范围和规则、怎样验收。把任务书交给 Agent 并要求执行，即可开始。
- **快速任务。** 几句话即可说明要改什么、范围和怎样算完成时，直接在对话中交代。Agent 执行后留下简短记录。

正式任务以可独立验收的用户结果为单位。总控 Agent 负责核对现状、按需拆分和分派、处理共享接口与代码冲突、审查、集成和验证。执行中遇到会改变已确认的范围、用户行为或验收标准的取舍，由总控带着影响和推荐交用户决定。

## 留档和验收

每项任务在 `docs/tasks/` 下建一个以日期和短标题命名的目录，例如 `2026-11-12-项目协作规范/`。正式任务保存 `任务书.md` 和 `记录.md`，快速任务只需 `记录.md`。补充要求、修复和复验写回同一任务的记录。

Agent 使用同一份[任务记录模板](templates/任务记录模板.md)，记录实际交付、验证结果和待处理项。快速任务可以每节只写一行。多 Agent 任务只需补充与集成、边界变化或后续维护有关的分工和决定。

交给用户验收时，提供可用的交付物和最短操作路径。构建、自动化、合成输入、真机实测及用户验收各按实际结果记录。Agent 在用户反馈后更新原记录，注明通过项或下一轮修复项。
