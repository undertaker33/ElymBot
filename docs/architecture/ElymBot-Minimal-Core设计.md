所有插件均可单独选择下载、安装和删除，包括 QQ 接入、定时任务、语音能力与工具插件。每项插件能力只在对应插件已安装且启用时可用。删除插件后停止其触发、收发或工具调用，App 的文本和视觉对话仍可独立运行。插件接口随实际插件所需能力逐步开放，下载来源、入口和插件数据的保留策略待定。

## 一次助手执行

1. App、定时任务插件或启用的接入插件向宿主提交统一输入及来源。QQ 插件先按 D07 完成去重、准入与分流。明确的内置管理命令由对应功能处理，普通对话交给 Agent。
2. 应用定位会话，读出本次生效人格、模型、渠道能力和可用工具。执行期间以这次选定的会话和设置为准。同一会话内顺序执行，不同会话可同时生成。每次运行及其增量和最终回复均归属发起会话。页面离开和会话切换只变更观察对象，回复继续生成并保存，应用内显示新消息提示。
3. 宿主装配模型输入并请求模型。收到完整回答就结束，收到完整的结构化工具调用就校验参数及作用范围，再顺序执行。同一批调用按 ID 回填结果，失败或拒绝也返回对应结果。
4. 将这一轮的工具结果放入上下文。下一次模型调用前重新计算预算，需要时先压缩、重建请求，再让模型决定下一步。遇到取消、超时或运行上限时结束并保留实际状态。已经产生业务效果但结果未知的工具调用需要查明状态后再决定是否重试。
5. 应用记录最终回复和交付状态，交由 App 或对应的接入插件投递。中间可显示必要进度。正式回复采用完整文本及支持的媒体，原生流式由模型能力和回复渠道共同决定。

Core 管理服务连接、模型和能力。文本和视觉共用会话、人格与上下文流程。支持结构化工具调用的模型才会收到工具定义，纯文本模型提供普通对话，遇到需要工具的请求时说明能力限制。语音识别插件可在应用装配上下文前将音频转成文本，语音合成插件可在宿主生成回复后将文本转成音频。QQ 插件负责平台消息收发与语音封装。具体首版模型名单和用户切换入口按 D03、D16 决定。

## 会话与上下文

- **主会话。** App 固定保留一个全局主会话，同一时间激活一个人格。切换人格后，新回复使用该人格并接续主会话原有历史。
- **人格专属会话。** 只能从对应人格的入口创建和打开。会话创建时固定归属人格，每轮读取该人格的最新配置。人格有专属会话时须先处理会话，列表支持批量删除。App 以会话 ID 隔离历史、摘要、检查点和运行状态，Core 从当轮会话取上下文。
- **外部会话。** QQ 接入后，手动绑定的本人私聊接续全局主会话。其他私聊和群聊按 D07 隔离，在 App 内只读。群聊回复使用该群可见的材料，回复仍发回触发本轮的渠道。
- **执行中的操作。** 当前会话生成结束后才可建点或回退。主会话同样在生成结束后才可切换激活人格。
- **请求装配。** 应用在模型调用前完成会话定位和材料选取。先保留宿主规则和生效人格，再加入完成请求所需的运行信息、所属会话的历史、当前用户消息或定时任务提示词、当前执行的完整工具调用和结果。工具定义独立交给支持它的模型。时间、时区和渠道能力只在当前请求需要时加入。
- **历史预算。** QQ 对话常由几个字到一两句话组成。以 64K 级上下文作为当前选型的设计基线，每次按所用模型实际可用的窗口计算。应用先预留输出额度，并计入人格提示词、当前输入、附件、工具定义和本次工具调用及结果，再用剩余 Token 预算选取当前会话的历史。达到压缩触发线时先压缩；压缩不可用或结果仍超限时，按下节处理。凭据由对应接入实现用于认证。
- **附件读取。** 单次读取按预算截断，给模型当前请求需要的片段，同时保留附件引用及截断标记。附件本身独立保留，后续可按需要再次读取。
- **个人助手体验。** 人格决定称呼、语气、回答习惯和偏好的表达方式。默认直接回答，只有需要完成具体操作时才调用工具。长期记忆在重构完成后另议。

## 会话检查点与历史读取

1. 应用按会话保存聊天历史和稳定轮次顺序。每个 App 会话都有独立的固定空点 1 和当前检查点。
2. `/mark` 在已完成轮次建点并设为当前点。`/checkpoint N` 回到指定点，`/reset` 回到当前点。回退事务删除本会话中该点后的对话、后续检查点及覆盖被删内容的摘要。新检查点可复用已释放的显示编号。
3. 上下文压缩保留原文。`HistoryRead` 由宿主绑定当前会话，读取仍保留的历史，包括摘要覆盖的原文。回退删除的记录从模型装配和历史读取中移除。

## 上下文压缩

1. **每次调用前检查。** 宿主在首次请求前以及工具结果回填后重新计算 Token 占用。接近有效输入上限时开始压缩，目标是为接下来的一批工具结果和最终回复留出空间。若模型服务实际报上下文超限，重新装配并进行一次有界恢复。
2. **先压缩已完成的历史。** 应用选出同一会话较早的完整轮次，只把这些材料发给摘要模型。有效摘要带上覆盖的消息范围，后续请求用摘要代替该范围的原文，最近的完整对话及原始会话记录继续保留。 [Re-UthCode 的完整历史选取](D:/project/Re-UthCode/src/uthcode/core/compaction.py:1107)
3. **本轮工具结果也能压缩。** 本轮较早、调用和结果均已完成的工具批次可整体转换为观察摘要。保留已确认事实、来源链接或附件引用、视频时间戳、失败状态和待核对事项。最新结果和仍在处理的调用保留对应关系。将来接入论坛或视频平台时，每次读取可以带回新材料，累计达到预算后再次压缩并继续当前轮次。
4. **用新请求验证压缩。** 应用提交摘要前检查覆盖范围，并用候选摘要装配一次请求，确认 Token 占用有实际下降。提交后使用新请求继续执行。每轮可多次压缩，受次数、用时与预算限制，同一批未变化的材料只尝试一次。失败或无降幅时保留上次有效摘要，从较旧的可选历史裁剪。若当前必要材料仍放不下，结束本次执行并说明限制。 [Re-UthCode 的降幅校验](D:/project/Re-UthCode/src/uthcode/application/context.py:608)

## 定时任务插件

- 插件记录所属会话和回复目标，通过 Android 调度在到期时触发同一个宿主 Agent。插件提交保存的任务提示词，宿主按该会话的有效范围和预算装配历史。回复归入所属会话，并通过记录的回复目标交付。任务面板的位置留给界面设计。
- 对话可以调用插件提供的工具创建和修改任务，由插件按会话权限处理。对话与编辑入口共用同一条任务记录。一次到期执行以任务 ID 和触发时点识别，重复调度复用同一个执行记录。删除插件后停止其后续调度。

## 运行与投递

- QQ 插件用平台事件标识去重，并向应用报告投递状态。应用分别记录回复生成与投递结果，渠道发送失败时可以针对该结果重试。进程中断后，用户能看到当前结果或中断状态。日志记录来源、阶段和失败原因，并过滤凭据和敏感载荷。
