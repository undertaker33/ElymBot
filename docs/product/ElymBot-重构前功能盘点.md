### D02 / D08 全局主会话与上下文切片

- **一个全局主会话。** App 对话直接进入主会话。用户手动选择 QQ Bot 和本人 QQ 聊天账号完成绑定，首版仅对应的 QQ 私聊可接续主会话。主会话可激活一个人格，切换人格后继续同一段历史。
- **外部会话自动隔离。** 所有 QQ 群聊和其他私聊按接收账号和 D07 规则分开保存，在原渠道正常交互，在 App 内只读。群聊消息保留来源和可见范围，回复回到触发它的渠道。
- **应用装配当前上下文。** 先确定会话，再按激活切片和渠道范围选取相关历史。回复生成期间，应用禁止切换人格、清除上下文或激活其他切片。清除上下文会建立新的起点。激活较早切片时，后续消息从切片结尾继续，全部原始聊天文本仍可查阅。 [Minimal Core 设计](../architecture/ElymBot-Minimal-Core设计.md)

### D11 会话内定时任务

安装定时任务插件后，用户在会话里说明要做什么、何时做，模型调用插件创建任务，并在同一会话显示任务及其计划。用户可以继续发消息修改，例如把「每小时检查」改成「每三小时检查」。到期时由插件发起执行，复用 D01 的宿主 Agent，回复追加到所属会话。 [OpenAI 官方定时任务教程](https://developers.openai.com/training/walkthroughs/scheduled-tasks)

直接编辑参考用户截图，提供任务标题、提示词、重复频率、间隔、重复结束条件，以及保存和暂停操作。对话修改与面板编辑作用于同一个任务。待确认的范围包括 QQ 会话入口、面板位置、一个会话内的任务数量和后台触发的精确度。宿主复用 D08 的上下文装配规则。

### D06 QQ 首次使用资料核对

从 2026-11-05 的[QQ 接入讨论](codex://threads/01a1ac32-22f5-7422-9df4-20ccc3ba316e)找回四条候选，另保留旧版作为对照。下面记录的是文档能确认的安装或接入门槛。

- **旧版 Ubuntu/proot + NapCat + Linux QQ + OneBot。** 以现有 ElymBot APK 的首次使用为对照，重点记录用户反馈的下载与安装失败在哪一步出现。
- **Ubuntu/proot + Yogurt Linux ARM64 + Milky。** 上游提供 Linux ARM64 包。沿用容器的组合仍要验证手机端的下载、解包和启动，同时需要可用的签名服务。 [Yogurt 安装文档](https://acidify.ntqqrev.org/docs/yogurt/start)
- **Acidify Core 直接接入 Android APK。** 官方列出的库目标包含 Kotlin/JVM 和 Linux ARM64，未列出 Android 构建目标。直接接入有机会省去用户另行安装协议端，需先验证 Android 构建、登录、签名及实际收发。 [Acidify Kotlin 接入文档](https://acidify.ntqqrev.org/docs/core/kotlin)
- **LLBot 纯协议 + OneBot 11。** 官方说明纯协议模式可省掉 QQ 客户端，LLBot 仍需要运行。若部署在另一台设备，首次使用会多出配置地址、连通性及登录步骤。能否手机本机运行，以及授权和登录流程需要验证。 [LLBot 模式说明](https://luckylillia.com/guide/introduction)、[LLBot 安装文档](https://luckylillia.com/guide/choice_install)
- **Lagrange V2 + Lagrange.Milky。** 单独运行协议端。若使用上游签名服务，需要完成白名单申请、GPG 验证和绑定实际使用的 QQ 号，这些步骤应计入用户首次配置成本。 [Lagrange.Milky](https://github.com/LagrangeDev/Lagrange.Core#providing-web-service-to-bot-applications)、[签名申请指南](https://github.com/LagrangeDev/SignApiGuide#自助申请)

验证的比较起点为全新环境，终点为完成登录并收到第一条 QQ 回复。2026-11-08 的资料核对未连接 ADB 设备。2026-11-11 用户确认后续验证完成，采用优化后的 Ubuntu/proot + NapCat + Linux QQ + OneBot。候选清单保留为调研记录。
